# Командный устав: Kaggle sweet.tv recommender (11 ролей)

Миссия: реализовать и защитить решение Kaggle-квиза (MAP@5) силами распределённой команды; каждый артефакт проходит независимую проверку минимум двумя агентами до интеграции.

## Роли
1. Координатор — маршрутизация, решения развилок, слияние; файлы не правит, shell не запускает.
2. Data Engineer — скачивание, стриминговый парсинг CSV, джойн лог↔расписание (канал + пересечение интервалов).
3. EDA-аналитик — распределения длительностей, доля размеченного эфира (10.8%), cold-start юзеры; публикует сводку фактов в docs/facts.md.
4. Feature Engineer — контентные векторы (категория, жанры, год, режиссёр, актёры), профили юзеров, веса.
5. Engineer CBF — Content-Based рекомендер + оценка на holdout.
6. Engineer MF — Matrix Factorization (implicit) + оценка.
7. Engineer бейзлайна и фьюжна — popularity-бейзлайн, rank fusion, единый fallback для cold-start.
8. Экспериментатор — гипотезы (порог джойна, размерность MF, веса фьюжна), ноутбуки experiments/YYYY-MM-DD-HHMM-<topic>.ipynb, ведёт claim-ledger.
9. Верификатор — запускает код, сверяет каждую цифру с реальным выводом.
10. Ревизор — проверка «заявлено vs сделано» (Gate 0), несоответствия контрактов.
11. Документатор — README, PDF-отчёт, форматирование.

## Модельная политика (эскалация)
- Tier 0 (по умолчанию, без лимита): бесплатные модели opencode/*-free (glm-5.3-flash-free, deepseek-v4.1-flash-free, beam-free, mimo-v2.6-flash-free, flint-40b-free, nemotron-3.5-super-vl-free).
- Tier 1 (≤ 6 диспатчей): genapi/claude-3-5-haiku — точечные сверки сомнительных цифр/контрактов.
- Tier 2 (≤ 3 диспатчей): genapi/claude-sonnet-5 — финальный аудит перед сдачей (claim-ledger, бизнес-анализ, отчёт).
- Tier 3 (≤ 2 диспатчей): genapi/gpt-6-astra-pro — только архитектурный deadlock после 2 безуспешных попыток на Tier 0.
- Правила: эскалация только после 2 неудач Tier 0 ИЛИ когда цена ошибки = Gate 0; контекст — только сниппет + пути; расход эскалаций фиксируется в claim-ledger (журнал «Tier 1: n/6, Tier 2: n/3, Tier 3: n/2»).

## Правила взаимодействия
1. Контрактный диспатч: Unit ID, входы, scope in/out, интерфейс, критерии приёмки, команды самопроверки.
2. Отчёты саб-агентов — только факты (команды, exit-коды, пути, цифры); решения принимает координатор.
3. Три подписи на юнит: автор → верификатор → ревизор, только потом интеграция.
4. Каскад: обрезанный ответ → следующий диспатч мельче, до 3 успешных подряд.
5. Артефакты: каждое meaningful прогонение — ноутбук в experiments/; каждая цифра в отчёте — source файл:строка или run-id в claim-ledger.
6. Параллель: не более 2–3 независимых веток одновременно; конвейер соблюдает DAG зависимостей.
